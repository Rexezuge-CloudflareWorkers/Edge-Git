# Edge-Git — Backend Data (D1/DAO Layer)

Scope: `packages/backend-data/**`. Parent index: `../../AGENTS.md`.

- All D1 access via DAOs over `D1Queryable`. `BaseDAO` extends the kit's (`@rexezuge/d1`): the **sql-first** `run(sql, bindings)` / `first` / `all` / `count` / `batch` helpers carry the retry engine and the `success: false` → `DatabaseError` normalization, so a `UNIQUE` failure can no longer reach a caller as an opaque 500. Every DAO takes the invocation's `SubrequestMeter` as a second constructor argument (the composition root hands each one the scope's counter), because the kit charges each statement against the meter it was **constructed with** and an unmetered DAO under-reports silently — it spends a subrequest the ceiling never saw. `withRetry` survives only as the escape hatch for a statement whose result shape the caller must inspect; on top of that sit static `findById`/`deleteOlderThan` and instance `findRowById`/`deleteRowsOlderThan`/`encodeCursor`/`decodeCursor`/`decodeCursorOrThrow` (`CursorCodec` from `@rexezuge/shared`; absent cursor decodes to `undefined`, a malformed one throws). `RepositoryDAO` (single-path case-insensitive `owner_ci/name_ci` reads, `listByOrgId/listByCollaboratorEmail/renameOwner`; `getByOwnerAndName` wraps failures as `DatabaseError` so git auth maps outages to 503, never a confusing 500; fork lineage via self-join alias), `UserDAO` (`createUser`/`upsertUser` with 0028 `id`/`current_email` columns, `newId()`/`newAnchor()`, `getById`/`getByEmail` (frozen anchor)/`getByCurrentEmail`, `getByUsernameCi`, `ensureUsername`/`setUsername` keyed on id-or-email, `setCurrentEmail`, batch `getByEmails`/`getByIds`), `NotificationDAO` (`insert` dual-writes `user_id`/`actor_user_id`; `listByUser`/`unreadCount`/`markRead`/`markAllRead` take `{userId, userEmail}` and emit `(user_id = ? OR (user_id IS NULL AND user_email = ?))` so pre-0028 rows still match), `UserEmailDAO` (**the kit's** (`@rexezuge/identity`), re-exported from `dao/identity.ts`: the `user_emails` address registry whose `register` re-points a revoked row but refuses a verified one — the upsert carries `WHERE user_emails.is_verified = 0`, so a claim that loses a race cannot re-point a row that is verified *now*; `get`/`resolveVerified`, `revoke`/`revokeAllVerified`, `listByUserId`), `NamespaceDAO` (global `user|org` registry: `claim/claimIgnore/release/isTaken`), `OrganizationDAO`/`OrganizationMemberDAO` (`owner|member`, `countOwners`), `RepoCollaboratorDAO` (`admin|write|read` grants; `user_id` dual-written, `getByUserId`/`listByUserId` alongside the address reads); `UserAccessTokenDAO`/`OrganizationMemberDAO`/`TeamMemberDAO` likewise gained `user_id` + `getByUserId`, `UserAccessTokenDAO` (hash lookup, expiry prune, per-user list, scopes via `token_scopes` only), `IssueDAO` (+ `CommentRow`, per-repo numbering via `COALESCE(MAX(number))`, `full_name` via `repositories` subselect), `PullRequestDAO` (numbering + reviews/comments + `pull_review_threads`/`pull_thread_comments` + review dismissal columns; base/head names via subselects), `ReleaseDAO` (`releases`/`release_assets` + `deleteByRepo`), `SearchDAO` (`repo_fts`/`issue_fts`/`pull_fts`/`code_fts` first, LIKE fallback; token/FTS/LIKE builders in `SearchQueries.ts`, same `*Queries.ts` pattern as `CollaborationQueries`).
- Utils: the D1 types, the retry engine (`executeWithRetry`/`D1_RETRY_DEFAULTS`), the error classifier (`isD1ErrorRetryable`, which checks the retryable list **first** so a blip costs one round trip rather than an outage) and `isMissingSchemaError` are the kit's, re-exported from `./utils`; `CursorCodec` lives in `@rexezuge/shared`. What stays here is D1 *domain*: `CollaborationQueries` (pure SQL builders) + `computeUnixCutoffSeconds/computeDateCutoffIso/pruneInBatches` (retention/batching). `crypto/aes-gcm` is a thin adapter over the kit's `encryptSecret`/`decryptSecret` (WebCrypto AES-GCM-256): it keeps `generateAESGCMKey` (key *issuance*, which the kit does not ship) and maps the envelope's `ciphertext` onto the `encrypted_*` column the schema already has, so adopting the kit did not require a column rename across a squashed baseline. backs the per-feature envelopes: `WebhookDAO` (key `WEBHOOK_ENCRYPTION_KEY_SECRET`), `MirrorDAO` (`MIRROR_ENCRYPTION_KEY_SECRET`), `ImportDAO` (`IMPORT_ENCRYPTION_KEY_SECRET`) — all extend `EncryptedDAO` (key required, fail closed), store envelope-only since migration 0027 dropped the plaintext columns, and decrypt on read with the decrypted value exposed under the legacy `secret`/`source_url` property names; hashing still lives in `@edge-git/shared/utils` (`CryptoUtil.sha256Hex`).
- Migrations in `migrations/0021_squash.sql` (single baseline squashed from 0001–0020: `users`/`namespaces`/`organizations`/`organization_members`, `repositories` + `repo_collaborators`, `user_access_tokens` with scopes/prefix, `issues`/`comments`, pulls (`pull_requests` + reviews/comments/threads/dismissal), `branch_protection_rules`, social (`repo_stars`/`repo_watches`/`repo_events`/`notifications`), collab (`labels`/`milestones`/assignees/reviewers), FTS (`repo_fts`/`issue_fts`/`code_fts` rowid-linked/`pull_fts`/`discussion_fts`/`snippet_fts` + triggers), `repo_webhooks`/`webhook_deliveries`, `releases`/`release_assets` metadata only (bytes in the DO), surfaces (`projects`/`discussions`/`wiki`/`snippets`), `teams`/`team_members`/`team_repo_grants` + `audit_logs` with org/repo scoping indexes, transfer (imports/mirrors/`deploy_keys`/`token_repo_grants`/`repo_security_settings`), `check_runs`, numbering UNIQUE backstop + `repo_number_counters`); `migrations/0022_normalize.sql` adds 3NF junction tables (`token_scopes`/`webhook_events`/`branch_protection_required_checks`/`repo_import_refs`); `migrations/0023_backfill.sql` backfills the junction tables from JSON via `json_each` (rerunnable `INSERT OR IGNORE`; DAOs dual-wrote with junction-first reads + JSON fallback); `migrations/0024_drop.sql` drops the JSON columns and stored `full_name` copies (junction tables + `repositories`-join aliases are the sole source; FTS triggers recompute names via subselect + a rename-refresh trigger); integration embeds all `*.sql` via `__INTEGRATION_MIGRATION_SQL__` (plus per-file `__INTEGRATION_MIGRATION_FILES__`, applied one file per `db.batch()` because D1 scopes PRAGMAs to the transaction; `applyMigrations(db, {from,to})` applies a range). `migrations/0028_user_identity.sql` is the user-identity migration and is deliberately **not** a table rebuild: D1 honours neither `PRAGMA foreign_keys = off` nor `PRAGMA legacy_alter_table = on`, and `defer_foreign_keys` does not suppress `ON DELETE CASCADE`, so the three `REFERENCES users(email)` clauses cannot be repointed without dropping rows — hence the frozen anchor. `UserIdentityUpgrade.int.test.ts` seeds every cascade edge, applies 0028, and asserts zero row loss + `foreign_key_check` clean. New DAOs: `TeamDAO`/`TeamMemberDAO` (`admin|member`, `countAdmins`)/`TeamRepoGrantDAO` (`deleteByTeam/deleteByRepo`), `AuditLogDAO` (`create`/`query` cursor-paginated with `resourcePrefix` + `queryOrgAudit` + `pruneOlderThan`).
- `src/dao/NumberingDAO.ts` — atomic per-repo numbering (`repo_number_counters`, migration 0021): single UPSERT ... RETURNING hands out distinct numbers under concurrency, seeded from `MAX(number)`; throws missing-schema-style when the table is absent so services fall back to the legacy loop.
- Token prune path: `UserAccessTokenDAO.pruneExpired(now, limit)` called from `TaskRegistry.pruneExpiredTokens`; retention constants come from `ConfigurationManager`, never hardcoded in DAOs.
- Layer 2 (L0-only): import only `@edge-git/shared` + the `@rexezuge/*` kit (`d1`, `errors`, `shared`, `identity`); never `backend-runtime`, `git-*`, `backend-services`, or `apps/*` (enforced by `no-restricted-imports`).
